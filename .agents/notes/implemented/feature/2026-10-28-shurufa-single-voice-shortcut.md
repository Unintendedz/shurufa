# Agent Note: Shurufa 只保留一个语音快捷键

Status: implemented

## Problem

用户试用后明确撤回三档模式、四个内置开关和长说明的界面，要求只有一个语音快捷键生效，并用键帽显示按键。

## Decision

本篇取代[原三档快捷键决定](2026-10-28-macos-configurable-voice-shortcut.md)在 Shurufa 中的多入口和 legacy 规则。其他 edition 保留旧行为。语音页只有「快捷键」（当前键帽、录制）与「触发方式」（系统 NSPopUpButton 的按住说话/切换）两行。按键页只留下语音设置入口；非语音的开关和配置保持可用。

用户明确授权的出厂值是右 Option + 按住说话。一次性迁移保留有效自定义键与 hold/toggle；legacy 单个修饰键转 hold、组合键转 toggle，无绑定转右 Option/hold。共享快照保存成功后才更新本地镜像和迁移标记。四个旧内置语音键置为关闭，运行时只匹配一个有效绑定，不再回退到其他入口。

键帽用固有文本宽度和左右 8 点内边距排版，左右侧别用 9 点文字、符号用 14 点。按键页固定切换开关的显示与原有绑定一致，原控制器和真实偏好仍决定是否生效；不把单按 Shift 与 Shift+空格合成一个控件。

跨窗口录音由后续[持续录音决定](2026-10-28-shurufa-single-voice-session.md)实现，本篇只记录快捷键与设置入口。

## Alternatives considered

- 保留旧兼容档但隐藏开关：代码改动少，但用户仍可能触发不可见的旧键，不符合单一绑定要求。
- 清除所有旧绑定并使用默认：迁移简单，但会覆盖用户已经录好的 Option+左方向键，所以保留有效绑定与明确模式。

### 双侧修饰键的开始判定

自定义单侧修饰键只在同组中确实只有该侧按住时开始。另一侧先按、绑定侧后按的组合与反向顺序一样，不触发录音。旧夹具只覆盖绑定侧先按；新增左 Command/Option 先按的用例在修复前退出 134，修复后退出 0。判断使用已收到事件记录的侧别，不增加等待时间或实体状态猜测。

### 恢复默认值

语音绑定和触发方式注册进语音节的可恢复键及设置探针。按键切换与语音通用字段恢复后显式写入原有默认值，避免共享合并把缺键理解成沿用旧文档；共享语音快照取当前偏好对象的 defaults，不再绕过测试套件或宿主自己的存储。Caps Lock 未存值时使用 Shurufa 已有的开启默认值，其他 edition 仍关闭，用户显式保存的关闭不变。

恢复不清语音服务、端点、模型和密钥：共享 `restored_to_defaults_for` 本来就保留这一整组，避免凭据留下却被改指向默认端点。回归覆盖关闭 Caps Lock、设置组合键/toggle/关闭语音后恢复、导出共享快照、重新载入与服务凭据保留；旧代码 Caps Lock 回归退出 134，修复后专项退出 0。

### 按实际能力校验组合键

macOS 专用语音绑定不占用 Linux 的 Ctrl+Space；Shurufa 也不占用已移除屏幕键盘的 Control+Shift+Command+K。偏好存储的保存、重载、修复和原生运行时创建、更新均使用所属 edition 校验；full edition 继续保留屏幕键盘组合键。原生录键预检对仍存在的 Control+Option+Shift+C/R/T 维护键给出明确冲突提示，与共享校验一致。不增加系统快捷键黑名单，用户主动录制的有效组合键仍由用户决定。

旧存储对空闲组合键的回归退出 101；修复后保存/重载、运行时创建/更新及原生预检通过。client-core 654 项全部通过；格式化通过，普通 clippy 完成。严格 `-D warnings` 被未改动的 `chunks_exact_to_as_chunks` 和既有测试初始化告警阻断，不把它写成全绿。

## Consequences

迁移测试覆盖无绑定、组合键 toggle、legacy 组合键、legacy 单侧修饰键、保存失败和重复运行。共享默认偏好通过校验。真实 AppKit 截图使用合成配置，实际键盘与系统输入法分发仍由用户验收。
