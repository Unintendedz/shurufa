# Agent Note: Shurufa 单一语音快捷键与跨窗口录音

Status: implemented

## Problem

用户实际使用后撤回三档模式和四个内置开关的设计：界面难读，失焦取消妨碍边查资料边说话，Option+左方向键有时不能结束录音。旧录音授权绑定原 IMK 客户端，失焦会清理采集和转写。

## Decision

本决定由用户通过监督者明确批准，取代[三档快捷键决定](../../implemented/feature/2026-10-28-macos-configurable-voice-shortcut.md)在 Shurufa 中的多入口、legacy 和失焦取消规则；其他 edition 保持原行为。

Shurufa 只提供一个快捷键，默认右 Option 与按住说话，保留用户已有的有效绑定与 hold/toggle；legacy 按原绑定语义迁移。界面只有快捷键（键帽与录制）和触发方式（系统 NSPopUpButton 的按住/切换）两行。按键页保留原有非语音配置能力，语音部分只有入口。键帽文字自适应，左右标记用较小字号。

录音由原控制器作为进程级所有者持有，焦点变化只清除原客户端的临时 marked text，不提交半成品。离开原窗口后实时文字只在不抢焦点的浮层显示。浮层始终提供完成和取消；录音期间使用只读 CGEventTap 监听结束键和 Esc，输入监控权限缺失时在浮层提供中文引导，保底按钮仍可用。Caps Lock 外接键盘与录音监听共用 `MSIMEEnsureInputMonitoringAccess` 的 IOHID 检查/异步申请，仅在主线程建立监听，结束后移除。结束时向当前可用的 Shurufa 文本客户端提交一次，否则写剪贴板并提示已复制。不注入键盘事件。

切换组合键不依赖上一轮 KeyUp 才能再次触发：新时间戳的非重复 KeyDown 是确定的新按下；同一事件从全局和 IMK 到达时只处理一次。完整控制器夹具已经证明有 KeyUp 时 Option+左方向键通过，缺 KeyUp 时原实现卡住；尚未观测用户那次系统事件，因此不把此复现等同于全部现场根因。

### 失焦测试的崩溃根因

`LiveVoiceControllerTest` 只分配控制器、未建立系统 IMKServer。直接调用产品 `deactivateServer:` 后，系统基类访问未初始化的内部状态，栈顶是 `IMKInputController deactivateServer:+24` → `MSIMEInputController deactivateServer:` → `main`，地址 `0x8`，进程退出码 139。这是测试夹具问题，不能作为失效文本客户端的产品证据。

夹具采用仓库韩文控制器测试的既有做法，只替换 Apple 基类 `deactivateServer:` 并计数，产品失焦方法完整执行。原窗口、新窗口和剪贴板投递均通过；TextStream 使用真实工厂分支，仅把麦克风、模型流、整理服务替换为合成数据。录音监听回调测试只传入内存事件，不向系统发送按键。测试以进程退出码和断言为准，空日志不代表通过。

Shurufa 的默认实时显示位置由后续[浮层预览决定](2026-10-29-shurufa-overlay-only-voice.md)改为仅浮层；本篇保留跨窗口所有者、代次与最终投递规则。录音期间的普通按键不再取消录音，见[按键不打断录音决定](../bug-fix/2026-11-03-shurufa-voice-keys-keep-recording.md)。

## Alternatives considered

- 继续把录音绑在原客户端：实现简单、能防止误写其他窗口，但无法满足用户跨窗口录音要求。
- 用辅助功能模拟粘贴到任意应用：覆盖面更广，但需要更大权限且会改变剪贴板与按键行为；用户接受无 Shurufa 文本焦点时复制到剪贴板，因此不用模拟键盘。
- 保留三个模式、隐藏内置开关：兼容代码更少，但仍有不可见的多快捷键行为，不符合只有一个键生效的要求。

## Testing

- 迁移保留已有绑定和两种模式；全新或无绑定配置使用右 Option/按住；其他内置语音键不触发。
- 进程内完整控制器测试覆盖组合键、单侧修饰键的再次结束、丢失 KeyUp、重复事件。
- 开始→切走→切回/不切回→结束，采集不中断，原窗口无半成品，最终文本只上屏一次；取消无提交、无整理请求。
- 浮层测试使用实际 AppKit 面板，检查完成/取消按钮、不可成为 key/main window、缺权限提示和已复制状态，并导出浅/深截图。安装仍以监督者审图为前提；系统真实键盘、其他应用 IMK 分发、权限弹窗与录音效果由装机后的用户验收。

### 语音简繁输出

语音桥接返回 `commit` 与引擎 `view`，没有普通按键转移的 `commit_context`。macOS 投递入口在缺 context 时使用同次返回的 view 作为上下文，沿用其 `script_conversion`，因此繁体输出对语音也生效。真实会话合成“汉语”的回归在修复前退出 134，修复后得到“漢語”并退出 0；没有改动其他平台桥接契约。

### 审查后的失败与投递处理

失焦后的失败提示保存取消前的录音所有者身份，因此无文本焦点时也显示错误。持久浮层采用与模式提示窗一致的跨 Space、全屏辅助和不参与窗口循环行为。最终投递先更新目标控制器的智能标点前文，再插入文本，并沿用语音统计来源。剪贴板复制复用既有的 Concealed/AutoGenerated 标记；写入结果决定提示“已复制”或“复制失败”。

回归先在旧实现复现：失焦错误不可见、最终前文仍为录音前数字、跨 Space 标志缺失均使测试退出 134；修复后三项专项测试退出 0。独立命名的真实 NSPasteboard 用合成值验证隐私类型，不触碰用户通用剪贴板。Space/全屏的系统呈现仍需用户验收，配置断言不冒充系统切桌面实测。

### 第二轮复审的源码修复与待验收项

HTTP 采集错误由服务先取消采集、再回调，因此错误回调只核对请求身份和代次，不把 `active == NO` 当作过期；错误提示资格直接取进程级所有者身份。语音结果被会话拒绝时显示“语音会话不可用，请重试”，不绕过代次校验去复制已被拒绝的结果。浮层在创建时即设置 Shurufa 的跨 Space 行为，启动前错误也沿用；繁体转换在插入与剪贴板分流前执行，剪贴板使用录音控制器的输出设置。

新增回归源码覆盖先停机再报错、失焦且 inactive 的失败提示、最终会话拒绝、繁体复制及启动前浮层标志。该切片落地时磁盘仅 45 GiB，按用户要求暂停构建；用户随后授权精简本地快照，可用空间恢复至 66 GiB。现已重新编译并运行 HTTP、持久录音、浮层和设置回归，4/4 通过。前一 HEAD `fd78a53` 的完整 ctest 是 211/213，仅 `shortcut`、`skin-preview` 两项既有失败。

DeepSeek 提出的“空格锁定后快捷键无法结束”不成立：第二次按下重置 locked，按住模式在随后的松开返回 Toggle，报告只判断了按下阶段。启动权限意图在失焦时被撤销，迟到的授权/拒绝回调保持忽略，不恢复旧意图。Shurufa 明确关闭统计；调用既有统计入口不意味着启用这项能力。

## Consequences

全局只读监听不能吞掉其他应用的快捷键；用户选定的组合键仍可能触发当前应用动作。主键不是修饰键的绑定在授权后改由[系统层吞键决定](../bug-fix/2026-10-31-macos-voice-shortcut-event-tap.md)处理。输入监控授权和系统安全输入期间，监听可能不可用，完成/取消按钮必须始终可用。保留用户选定的组合键，不擅自追加系统快捷键黑名单。

### 录音监听回调边界

只读 CGEventTap 回调只捕获 NSEvent 和 handler，然后异步交主队列。音频停止、互斥锁和 AVAudioEngine 拆卸不在 tap 回调栈上执行；超时恢复也在主队列检查保留的 tap 仍有效后执行。监听保留至最终投递或取消，使处理期间 Esc 仍能取消。handler 核对录音代次，排队的旧事件不能取消下一次录音；终结时重置快捷键状态，不依赖可能被丢弃的旧 KeyUp。不能在开始绑定监听时重置，因为当前按住手势刚刚启动录音，还需要接收松开。

合成回归验证事件入队后音频停止计数仍为零、主队列运行后只停止一次、同一结束键重复到达和上一代 Esc 无副作用，并覆盖处理期间 Esc、提前 final 后再次右 Option、上一代 KeyUp 丢弃后新松开仍能结束。这修复了源码中确定的同步阻塞调用链，但未取得用户所报卡死现场，不能声称已证明那次故障由此引起。Caps 的 HID 入口在 Shurufa 中由[系统 Caps 决定](../simplification/2026-10-29-shurufa-system-caps-lock.md)关闭，其他 edition 继续使用授权帮助函数。

## Duplicate shortcut delivery

Option+左方向键的同一次按键会从 IMK、录音 tap 和 AppKit 全局监听进入控制器。异步 tap 在 KeyUp 后才到达时，旧状态机已经不 active，会再切换一次；最终投递重置手势后，迟到的全局副本还可能重新开始录音。真实控制器配合合成音频和客户端在修复前复现了第一次开始被重复事件提前结束。

Shurufa 的进程内回执按事件类型、物理键、修饰键和系统时间戳去重，并先记录结果再执行切换。回执跨手势重置和控制器转移保留；新的时间戳仍作为下一次按键处理。不设时间窗口，不保存字符或按键日志。真实控制器回归覆盖 IMK→KeyUp→异步 tap、结束后全局副本、转移到另一个控制器，以及下一次合法按键仍可开始。
