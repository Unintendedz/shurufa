# Agent Note: Shurufa 候选词决策链五层重构与分阶段演进

Status: proposed

## Problem

自 `fork-point/msime-2026-10-27` 分叉以来，Shurufa 围绕候选质量、重排、纠错、上下文与调频已连续落地十余次定向修复，但用户日常打字的真实体感仍然两极分化：当光标前存在高辨识度上文且正解幸存于前排窗口时，神经重排可以非常精准；但在无上文、短词、口语短句和常规全拼/双拼输入中，仍反复出现荒诞候选或正解被埋在多页之后的现象。同时，计划接入的「打字内联 Emoji」如果直接开启既有 `mixed_input.emoji`，会立即与逐键神经重排、停顿精排、次选下沉、英文短前缀补全和光标前缀编辑正面冲突。

根因审计确认，问题不是单次调参不够细，而是六处底层结构缺陷相互放大：

1. **词库 `weight` 是分档序数键而非词频概率**：锁定词库 `msime-pinyin.db`（`dict-v2.0.24`）存在严重语域偏斜与顶部饱和（如 `tbl_2_z` 中「证券」权重 `5,744,085` 为「知道」`500,000+` 的 11 倍，216 个常用双字词挤在 `500,000–510,000` 区间、`ln` 差仅 `0.006 nat`，70% 词条低于 `10,000`），且单字与多字词不在同一统计口径；词级基线 `top1` 仅 `0.755`。
2. **词网格 `edge_log_prob` 存在 27–38 nat 人工断崖**：`crates/engine/src/lattice/decode.rs` 对单字边计算 `ln(w) - ln(1e6)`，对多字边计算 `ln(w) + 20 * (k - 1)`，切分方式本身制造的断崖比整个词频动态范围（约 `3.2 nats`）高出一个数量级。过去三周的大部分高复杂补丁——纠错单字归一项补扣 `ln(1e6)`、隔音备选每音节扣 `30 nats`、指物代词「它」双证据补边、356 条静态动宾离合词表、短串 5 常量静态先验护栏——本质都是对同一量纲错误的下游补偿。
3. **打分器分裂与单位矛盾**：4.5 MB 键盘模型在引擎内与 `input-runtime::rerank_pick` 每键重复推理两遍，且引擎内路径重排、外层整句重排与词典同音提升各用一套混合公式；同时 `crates/engine/src/quanpin/dictionary.rs` 与 `shuangpin/dictionary.rs` 误将自然对数主分当作 `log10`，把万象 `.gram` 查询值乘了 `LOG10_E (0.4343)`；旧 `msime-bigram.bin` / `trigram.bin` 仅含 100 万条维基语料且截断负 PMI（只加不减）。
4. **搜索早剪与八道隐式排座叠加**：默认 `beam = 32` / `nbest = 12` 早剪，之后候选依次穿过词典查询、备选切分升位、整句插入、引擎内重排、个人上下文/同音提升互斥分支、固定排位与混输、runtime `rerank → demote_runner_up_readings → normalize_online_slots` 以及异步停顿精排；每层只看行号、来源编号和布尔标记，前序分数丢失，正解被剪或跌出首页后无法补救。
5. **个人学习直接改写静态权重**：`crates/engine/src/user_dictionary/ranking.rs` 的 `plan_weights` 把选中词直接写成 `leader + 1000` 或中点，与出厂词频共用同一整数列并回流污染词网格 `ln(w)`，被迫再叠加 `200,000 / 8×` 核心词护城河。
6. **评测体系缺少分阶段归因与真实体感指标**：现有 `convert_eval` 样本偏小、缺少现代口语聊天集、不区分「词表未覆盖 / 搜索被剪 / 排座掉出首页」，也缺少名次尾部 `p90/p95` 与首选抖动率，导致优化容易在噪声上过拟合。

## Proposal

在不追求兼容上游 `msime` 历史名次基线与旧词库冻结约束的前提下，将 Shurufa 的候选决策链按五层边界分阶段重设计，并采用「先归因建基线、先立纯函数槽位分配器交付 Emoji、再逐层替换底座」的演进路线：

### 目标五层架构

1. **L0 数据底座（同源一致）**：
   - Shurufa 独立版本化并校验哈希的基础词表与语法模型，采用同源的**万象开源词表 + 万象 LTS `.gram`**，确保词频先验与搭配分出自同一多语域语料、口径自洽，避免单人维护重型语料清洗管线。
   - 先核实万象词表许可证与 373 MB `.gram` 的 mmap 常驻内存，修复 `LOG10_E` 单位矛盾。
   - 旧 `msime-bigram.bin` / `trigram.bin` 仅保留作 `2×2` 对照与回滚基线，新路径默认弃用，不做双模型混算。
2. **L1 统一概率搜索（真噪声信道）**：
   - 词网格按 `log P(按键串 | 读音路径, 方案) + log P(词路径 | 上文)` 统一建模，全拼/双拼切分、模糊音与纠错边进入同一对数概率刻度，废除 `edge_log_prob` 的 `27–38 nat` 人工断崖。
   - 搜索产出带**稳定 ID、候选类型与分项特征**的候选池，不再由搜索层隐式决定首页排座。
3. **L2 唯一校准打分器**：
   - 合并现有三套神经混合公式，消灭 4.5 MB 键盘模型每键重复推理；所有主候选通过统一线性组合 `S = S_search + α·f_neural + β·f_collocation + γ·f_personal` 评分，系数在留出集拟合而非手写魔数。
   - 25 MB 停顿精排模型在异步线程对同一批候选 ID 补算分数；**首发策略锁定首次展示后的第 1 名**（停顿精排仅优化第 2–6 名，用户一旦导航或翻页立即冻结当前页，输入代次变化则丢弃旧结果），仅在后续留出集证明「空格净救回显著高于首位翻转误伤」时才考虑放开高阈值首位翻转。
4. **L3 独立个人学习叠加层（永不改写静态词频）**：
   - 废除 `plan_weights` 对静态 `weight` 的直接覆写；个人选择写入追加式事件日志，按约 30 天半衰期指数衰减派生个人计数，评分采用与静态先验正比的平滑叠加 `P(w|音) ∝ α·P_static(w|音) + n_user(w)`：高频核心词因先验质量大天然抗单次误选，低频专名/新词在少量选择后自然上升。
   - 区分**进首屏**与**竞争首位**：首次明确选择冷门专名即可在下次同码获得首屏召回席位（第 3–5 位），连续 2–3 次明确选择才竞争首位；空格接受原首位不记作明确改选；显式「置顶」作为 L4 硬约束立即生效；上屏后紧接退格删除整段文本即确定性回滚该次学习事件，并保留显式撤销入口。
5. **L4 唯一纯函数槽位分配器 `SlotAllocator`**：
   - 遵守 [ARCHITECTURE.md](../../../docs/ARCHITECTURE.md) 边界：`SlotAllocator` 作为无状态纯函数位于 `crates/engine`，输入仅接受「稳定 ID + 校准分 + 候选类型」，禁止依赖行号和零散布尔位；`crates/input-runtime` 在逐键呈现与异步停顿精排返回时**统一调用同一个纯函数**组装展示页。
   - 中文主候选拥有核心槽位；英文补全、内联 Emoji、自定义短语作为纯后置提供方只落入声明式配额槽，绝不参与 L2 主评分，也不破坏中文相对次序。
   - **反叠加硬约束**：`SlotAllocator` 每接管一段旧排座职责，必须在同一次提交中删除被取代的旧排座工序，绝不叠成「第 9 道工序」。

### 分阶段演进路线

- **Stage 0（归因评测基线 + 冻结魔数补丁）**：
  - 扩展评测集（新增现代中文口语/聊天样本集，以及历史补丁回归样本集）；
  - 改造 `convert_eval` 输出**分阶段失败归因**（词表 OOV / 解码搜索剪枝 / 呈现排座掉位）、**正解名次 `p90/p95`**、**停顿前后第 1 名翻转率（抖动率）**，以及关闭学习与开启全链路时的对照基线；
  - 从本阶段起**停止新增启发式魔数护栏**。
- **Stage 1（立 `SlotAllocator` + 干净交付内联 Emoji）**：
  - 在 `crates/engine` 落地纯函数 `SlotAllocator` 并由 `input-runtime` 在逐键与停顿精排后统一调用；
  - 将 Shurufa 内联 Emoji 作为首批纯后置提供方接入（基于清洗精选的 `中文词 → [emoji...]` 映射表：零肤色/性别冗余/日文方块字/带框数字、单字仅限具象情绪白名单、现代中文口语别名补齐、固定第 3 位/首页最多 1 个、独立本地 MRU 偏好、原生设置页开关），完全绕开旧 `queries.rs` 混排路径，并用性质测试锁死停顿精排前后中文顺序与英文/Emoji 槽位零错位。
- **Stage 2（修 `LOG10_E` + 万象同源词表与真概率解码 `2×2` 实验）**：
  - 核实万象词表许可与 mmap RSS；修复 `LOG10_E` 单位 Bug；
  - 离线构建 Shurufa 固定版本的万象同源词表与平滑概率解码器，跑 `2×2` 对照矩阵（旧/新词库 × 旧/新评分器）；
  - 验收通过后切换到新底座，逐个删除 `extra_syllables` 扣分、纠错 `ln(1e6)` 补扣、356 条 `SEPARABLE_VO_COMPOUNDS`、指物代词补边与旧 `msime-bigram/trigram.bin` 依赖，并保留全部历史错例作为永久回归集。
- **Stage 3（统一单遍打分器 + 停顿锁定首位）**：
  - 合并三套神经混合公式，消灭 4.5 MB 模型每键重复推理，留出集拟合权重；
  - 停顿精排默认锁定首绘第 1 名只精排第 2–6 名，验收端到端 Apple Silicon 按键到首绘 `p95 < 16 ms` 与抖动率归零。
- **Stage 4（独立个人学习叠加层）**：
  - 用追加式衰减日志 + 贝叶斯叠加层替换 `plan_weights` 静态权重改写，接入首屏专名召回、退格确定性撤销与置顶 L4 硬约束。

## Alternatives considered

### 为什么不直接打开既有 `mixed_input.emoji` 并继续微调参数？
最强理由是改动量极小、当天即可上线。但源码审计证实既有 `mixed_emoji` 在 `queries.rs` 中跑在固定排位、逐键神经重排、停顿精排和 `runner_up_order` 之前，开启后会立即撕裂锚定关系、楔入英文自动补全席位、在光标前缀编辑时静默吞字，并让裸 CLDR 单字与方块汉字污染首页；继续往旧管线叠护栏只会加深打地鼠循环。

### 为什么不从零自建多语域语料库与词级回退 n-gram？
最强理由是统计口径 100% 自主可控。但 Shurufa 是单人维护的独立项目，大规模现代口语/通用语料收集、清洗、切词、版权审计与持续迭代成本远超单人维护上限；直接采用同源的万象开源词表与万象 LTS `.gram` 同样能保证词频与搭配出自同一语料，同时把精力集中在解码、打分、学习与交互闭环上。

### 为什么不严格冻结所有新功能，等五层全部重写完再做内联 Emoji？
最强理由是架构最纯净、无需在过渡期维护静态槽位提供方。但全栈重写横跨评测、词库、解码、打分与学习四个大阶段，过长的零可见产出周期会让个人项目失去验证反馈与推进动力；提前立起 `SlotAllocator` 纯函数接口并接入纯后置的 Emoji 投影，既不依赖尚未建成的统一概率分，又能立刻把新接口跑在真机上并确保后续阶段无需返工。

### 为什么不让神经模型直接取代 n-gram 作为唯一主解码器？
最强理由是长句语境上限更高。但无上文短词、冷门专名与固定表达上，小型本地字级神经模型方差远大于平滑词频/搭配模型，这正是现状「长句超神、短词离谱」的成因之一；由同源统计模型负责高下限主解码、神经模型作为单遍校准特征负责语境消歧，在 Apple Silicon 本地延迟与下限稳定性上都更优。

## Acceptance criteria

- **Stage 0**：`convert_eval` 支持分阶段失败归因（未覆盖 / 搜索剪枝 / 排座掉位）、名次 `p90/p95`、停顿首位翻转率输出，并固化包含现代口语短句与历史错例的盲测基线报告。
- **Stage 1**：`crates/engine` 提供无状态纯函数 `SlotAllocator` 且 `input-runtime` 逐键与停顿路径共用；Shurufa 支持清洗版内联 Emoji（如 `sikao → 1. 思考 / 3. 🤔`）与原生设置开关；性质测试验证停顿精排前后中文顺序与英文/Emoji 槽位零错位，关闭 Emoji 后中文候选逐条与基线一致。
- **Stage 2**：修复 `LOG10_E` 换域 Bug；完成 `2×2` 对照实验且「新词表 + 真概率解码」在无神经模型冷启动下显著超越当前词级 `top1 (0.755)` 与口语集表现；全部历史补丁错例回归通过后删除旧断崖补丁。
- **Stage 3**：4.5 MB 模型每键仅推理一次，停顿精排首发锁定首绘第 1 名，Apple Silicon 端到端按键到首绘 `p95 < 16 ms`，首位抖动率受控。
- **Stage 4**：独立个人叠加层替换 `plan_weights` 权重改写，合成回放验收「单次误选不击穿高频词、首次明确选专名进首屏、2–3 次竞争首位、退格删除即撤销学习」。

## Risks

- **过渡期「第 9 道工序」风险**：Stage 1 提前落地 `SlotAllocator` 时若未同步清理它接管的旧排座代码，会反而增加管线层数；必须以单测和代码审查严格执行「接管即删除旧工序」。
- **万象资源许可与内存占用风险**：Stage 2 切换万象词表前必须逐项核实词表与 `.gram` 许可证兼容性，并在真机实测 373 MB `.gram` mmap 后的常驻 RSS 与冷启动首键耗时。
- **词库切换引发旧习惯落差**：彻底放弃旧 `msime-pinyin.db` 分档权重后，部分熟悉旧排序的词条默认位次会变化，必须依靠 Stage 0 的无偏盲测集与 `2×2` 实验确认净收益显著为正，并保留旧词库回滚能力。
- **停顿锁定第 1 名的指标权衡**：锁定首次展示第 1 名会彻底消除「准备按空格时第 1 名跳变」的挫败感，但也会放弃停顿模型把原本排第 2–3 名的正解拉回第 1 名的那部分收益；该收益应靠 Stage 2/3 提高**逐键首绘第 1 名准确率**来补齐，并持续用净收益数据评估未来是否开放高阈值翻转。
